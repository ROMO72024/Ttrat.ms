# حل تعارض APK والحفاظ على أسماء المعلمة

هذه التعليمات تعتمد على فحص ملفات APK الفعلية من GitHub. لا تحتاج إلى حذف الشيت أو إعادة إدخال أسماء الطلاب.

## النتيجة المؤكدة

| النسخة | الإصدار | بداية بصمة شهادة التوقيع |
|---|---|---|
| [تشغيل النسخة القديمة](https://github.com/ROMO72024/Ttrat.ms/actions/runs/34772647543) | 1.0.2-debug، رقم 3 | da5b6e4b964e |
| [التشغيل الأخير قبل الإصلاح](https://github.com/ROMO72024/Ttrat.ms/actions/runs/35128162340) | 1.1.1-debug، رقم 5 | f9df1aa6b414 |

كلتاهما تحمل المعرف `ps.ghars.sessions.debug`، وتوقيعاهما سليمان منفردين ولكنهما مختلفان. APK القديم في Actions مطابق بايتًا للملف الذي أرفقته. لذلك كان Android يرفض تثبيت الجديد كتحديث للقديم.

البصمتان الكاملتان SHA-256:

- القديمة: `da5b6e4b964ed2f0d79d045b8c6e5de505ea6a156bdf3844b67ee907cbaa049e`.
- الجديدة: `f9df1aa6b41496b4e4250c1cc4099fc808eccc3ad028dab38056ab0515025b41`.

كان سير العمل يوزع Debug، ولم يحفظ مفتاحه في مرفقات التشغيل. خطوات توقيع Release كانت متخطاة، وسجل التخزين المؤقت يحفظ مجلدات Gradle دون مجلد المفتاح `.android`. لا يوجد مفتاح توقيع في المشروع الأول المرفق. لا يمكن استرجاع المفتاح الخاص من APK.

إذا كانت لديك نسخة مستقلة من المفتاح القديم المطابق، يمكن توقيع تحديث مباشر به؛ هذه التعليمات تعالج الحالة التي لا تتوفر فيها تلك النسخة. [مرجع Android](https://developer.android.com/studio/publish/app-signing).

## 1. احفظ الأسماء من التطبيق القديم

1. افتح تطبيق المعلمة الموجود حاليًا.
2. افتح «الإعدادات» ثم «نسخة احتياطية مشفرة».
3. اختر كلمة مرور من 8 أحرف على الأقل واحفظها.
4. احفظ ملف `.ghars` في التنزيلات، وانسخه إلى الكمبيوتر أيضًا.
5. أبقِ التطبيق القديم مثبتًا إلى أن تتحقق من نقل الأسماء والجلسات والحضور.

ملف APK نفسه لا يحتوي الطلاب الذين أُدخلوا على الهاتف. المطلوب ملف النسخة الاحتياطية من داخل التطبيق.

## 2. ثبّت مفتاحًا واحدًا للإصدارات القادمة

إذا كان لديك مفتاح دائم محفوظ في أسرار GitHub الأربعة بالفعل، أعد استخدامه. لا تولد مفتاحًا مختلفًا لكل بناء.

إن لم يكن لديك مفتاح، افتح PowerShell في مجلد المشروع على Windows مع JDK 17، ثم شغّل مرة واحدة:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\create-signing-key.ps1
```

ينشئ المفتاح داخل `Documents\GharsSigning`. يحفظ معه `github-secrets.txt`، ولا يكتب فوق مفتاح موجود. احتفظ بالملفين خارج مستودع GitHub وبنسخة أخرى لديك.

افتح المستودع ← Settings ← Secrets and variables ← Actions ← New repository secret. انقل كل قيمة من ملف التصدير إلى الاسم المطابق:

| اسم السر | ما تنقله |
|---|---|
| GHARS_KEYSTORE_BASE64 | السطر الطويل تحت الاسم نفسه |
| GHARS_STORE_PASSWORD | كلمة المرور تحت الاسم نفسه |
| GHARS_KEY_ALIAS | قيمة الاسم المستعار |
| GHARS_KEY_PASSWORD | كلمة المرور تحت الاسم نفسه |

لا ترفع `github-secrets.txt` أو ملف المفتاح ضمن ملفات المشروع. المفتاح الجديد سيوقّع التطبيق المستقر، ولا يطابق مفتاح Debug القديم بأثر رجعي.

## 3. البناء من GitHub

1. بعد اعتماد تعديل سير العمل، افتح Actions ← Build stable APK.
2. اضغط Run workflow، واختر main، ثم Run workflow.
3. بعد نجاح التشغيل، نزّل `ghars-stable-apk` من Artifacts وفك الضغط.
4. ملف التثبيت هو `ghars-stable.apk`. معه `signature.txt` و`package.txt` للتأكد من شهادة الإصدار ومعرفه.

عمليات Push وPull request تجري الفحوص فقط. بناء APK الموقّع متاح بالتشغيل اليدوي بعد إعداد الأسرار، ولا تُرفع نسخ Debug للتوزيع.

## 4. نقل البيانات مرة واحدة

جرّب أولًا ببيانات اختبارية على هاتفك.

1. ثبّت `ghars-stable.apk`. يظهر باسم «أخصائية غرس · المزامنة»، ويعمل بجانب التطبيق القديم بمعرف `ps.ghars.sessions.transfer`.
2. أدخل كود الأخصائية نفسه. أول دخول يحتاج الإنترنت.
3. افتح الإعدادات ← «استعادة نسخة»، واختر ملف `.ghars` وأدخل كلمة مروره.
4. راجع المعلومات المعروضة ثم وافق على الاستعادة داخل التطبيق الجديد. الاستعادة تستبدل البيانات المحلية في التطبيق الجديد؛ راجع أي بيانات أدخلت فيه مسبقًا قبل ذلك.
5. تحقق من عدد الأسماء، ومن عدة ملفات وخطط وجلسات وحضور. لا تعتمد النقل بناءً على ظهور أسماء قليلة فقط.
6. بعد الاستعادة، فعّل «رفع الأسماء الحالية وتفعيل المزامنة»، ثم «رفع تعديلات الهاتف» عند الحاجة. راجع أي اختلافات تظهر مع بيانات الشيت.
7. تحقق من الأسماء في الشيت ومن نجاح المزامنة. احتفظ بالنسخة الاحتياطية وبالتطبيق القديم حتى التحقق الكامل.

هذه أول مرة انتقال إلى التطبيق المستقر، وليست تحديثًا مباشرًا لنسخة Debug القديمة. بعد الانتقال، حافظ على المعرف `ps.ghars.sessions.transfer` والمفتاح نفسه، وارفع `versionCode` عند إصدار تحديث جديد. بذلك تقبل النسخة المستقرة تحديثاتها التالية دون حذفها.

إصلاحات المزامنة والشعار والكود الواحد موجودة في المصدر الحالي. طريقة تحديث Code.gs وترتيب الشيت في START-HERE-AR.md ما زالت صالحة؛ تعليمات التوقيع وأسماء ملفات APK في هذا الدليل تحل محل تعليمات البناء السابقة.

## ما تحقق بالفعل

تم تنزيل نسختي APK من Actions وفحص توقيعيهما باستخدام Android apksig 8.7.3، ومقارنة معرفيهما وإصداريهما. الفحص القديم والجديد نجح منفردًا، والبصمتان مختلفتان. تعديل سير العمل لا يغيّر ملفات Java أو البيانات أو واجهة التطبيق.

لم يُختبر النقل على هاتف المعلمة أو على نسختها الاحتياطية الفعلية. فحوص GitHub تؤكد البناء والاختبارات، وتجربة النسخة الاحتياطية على هاتف اختبار هي خطوة التحقق من نقل بياناتها.
