# نسخة دائمة وتحديثات تحافظ على البيانات

> تحديث 1.1.1: استخدم `START-HERE-AR.md` لإعداد الأسرار والبناء. سير العمل الحالي يبني ملفات APK الموقعة على push أو Run workflow، ولا يحتوي خيار `signed_release` ولا يوزع Debug. أسماء المخرجات ومسار النسخة المستقلة موضحان في الدليل الحالي. أوامر إنشاء المفتاح وتحويله أدناه تبقى صالحة عند الحاجة؛ بقية أمثلة تشغيل 1.1.0 تاريخية.

يقبل Android تثبيت تحديث فوق تطبيق موجود عندما يتطابق **معرّف التطبيق ومفتاح التوقيع** ويكون رقم الإصدار مناسباً. لذلك يلزم مفتاح توقيع دائم للنسخة المستخدمة يومياً. [شرح توقيع التطبيقات من Android](https://developer.android.com/studio/publish/app-signing).

نسخة `debug` المخرجة تلقائياً من GitHub للتجربة الأولى، ومعرّفها `ps.ghars.sessions.debug`. مفتاحها يولَّد في بيئة البناء وقد يختلف بين تشغيل وآخر. نسخة `release` معرّفها `ps.ghars.sessions`؛ لا تستبدل نسخة التجربة، ويمكن أن توجد النسختان على الهاتف. انقلي البيانات بتصدير نسخة مشفرة من التجريبية واستعادتها في الدائمة، ثم أوقفي تذكيرات النسخة التجريبية أو احذفيها بعد التحقق من النقل لتجنب تنبيهين.

أي ملف APK مرفق باسم **غرس · معاينة** يستخدم المعرّف المستقل `ps.ghars.sessions.preview` للتجربة المحلية، ويحتاج أيضاً إلى التصدير والاستعادة عند الانتقال إلى النسخة الدائمة. لا يعاد استخدام مفتاح المعاينة للإنتاج، ولا يُرسل مفتاحه الخاص مع المشروع.

## إنشاء مفتاح مرة واحدة

على كمبيوتر موثوق مثبت عليه JDK، افتحي الطرفية داخل مجلد خاص خارج مستودع المشروع ونفذي:

```text
keytool -genkeypair -v -keystore ghars-release.jks -storetype JKS -alias ghars -keyalg RSA -keysize 3072 -validity 10000
```

سيطلب كلمة مرور مخزن المفاتيح وبيانات تعريف المالك ثم كلمة مرور المفتاح. يمكن استخدام كلمة مخزن المفاتيح نفسها للمفتاح. احفظي ملف `ghars-release.jks` وكلمات مروره في مكان آمن مع نسخة ثانية. لا تنشريه في GitHub ولا تضعيه داخل ZIP المشروع. فقدانه يمنع توقيع تحديثات بنفس هوية النسخة.

لإعداد سر GitHub الذي يمثل الملف، شغلي في PowerShell من المجلد نفسه:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes((Resolve-Path '.\ghars-release.jks'))) | Set-Clipboard
```

المحتوى الموجود بالحافظة هو المفتاح الخاص بصيغة نصية، وليس تشفيراً له. ألصقيه فقط في السر المخصص أدناه، ثم امسحي الحافظة.

## إضافة أسرار GitHub

في المستودع: **Settings → Secrets and variables → Actions → New repository secret**. أضيفي:

| اسم السر | القيمة |
| --- | --- |
| `GHARS_KEYSTORE_BASE64` | النص المنسوخ من أمر التحويل السابق |
| `GHARS_STORE_PASSWORD` | كلمة مرور ملف المفاتيح |
| `GHARS_KEY_ALIAS` | `ghars` إذا استخدمت الأمر كما هو |
| `GHARS_KEY_PASSWORD` | كلمة مرور المفتاح |

افتحي **Actions → Build APK → Run workflow**، وفعّلي `signed_release`. سير العمل يرفض بناء النسخة الموقعة إذا كان أحد الأسرار ناقصاً. بعد النجاح نزّلي `ghars-signed-release-apk` وثبتي `app-release.apk`.

## تحديث لاحق

احتفظي بمعرّف التطبيق والمفتاح نفسيهما. عند تعديل الشيفرة لإصدار جديد، زيدي `versionCode` في `app/build.gradle` من 1 إلى 2 ثم 3 وهكذا، وعدّلي `versionName` مثلاً إلى `1.0.1`. أعيدي تشغيل البناء الموقّع بنفس الأسرار. خذي نسخة احتياطية ثم ثبّتي APK الجديد فوق النسخة الموجودة؛ لا تحذفي التطبيق أولاً.

إذا رفض أندرويد التحديث، لا تمسحي البيانات لمعالجة المشكلة مباشرة. تحققي من أنك تستخدمين النسخة الصحيحة ومن ثبات المفتاح ورقم الإصدار. صدّري النسخة الاحتياطية قبل أي إعادة تثبيت.

سير العمل ينتج ملف APK للتثبيت الخاص بالمدرسة. لم تُهيّأ عملية نشر على متجر Google Play، ولا يدل توقيع الملف على نشره أو مراجعته من المتجر.
