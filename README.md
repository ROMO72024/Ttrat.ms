# غرس | متابعة الجلسات

<div dir="rtl">

تطبيق أندرويد خاص بأخصائية **مدرسة وروضة غرس الحديثة** لتنظيم جلسات النطق والعلاج السلوكي، بهوية مأخوذة من شعار المدرسة. يعمل على أندرويد 8 فأحدث، ويعمل بعد التثبيت دون إنترنت أو حساب مستخدم.

تتطلب الواجهة نسخة محدثة من **Android System WebView** على الهاتف. إذا كان الجهاز قديماً ومكوّن العرض لم يُحدّث منذ سنوات، حدّثيه قبل تجربة التطبيق؛ الاستخدام بعد ذلك يبقى دون إنترنت.

## ما الذي يقدمه؟

- ملفات طلاب قابلة للبحث: الاسم، الصف أو الركن، الفترة، بيانات التواصل، الأهداف والملاحظات.
- خطة مستقلة للنطق وخطة للعلاج السلوكي لكل طالب: إجمالي الجلسات والعدد المطلوب أسبوعياً والمنجز والمتبقي.
- جلسات فردية أو جماعية، مع حضور وغياب وملاحظة وتقييم تقدم مستقل لكل طفل.
- جدول أسبوعي، عرض اليوم والأيام القادمة، وتكرار الجلسات في أيام مختارة مع كشف تعارض مواعيد الأخصائية.
- إنهاء الجلسة وإلغاؤها وتعديلها، وملاحظات عامة للجلسة وسجل زمني داخل ملف الطالب.
- تذكير قبل الجلسة بمدة تختارينها، وتذكيرات خاصة، ومنبّه برنين متواصل واهتزاز وإيقاف أو تأجيل خمس دقائق. يتوقف الرنين تلقائياً بعد خمس دقائق إذا لم تتم متابعته.
- منبّه تلقائي عند بدء كل جلسة مجدولة، بالإضافة إلى التذكير المسبق الاختياري. اختيار صفر دقيقة ينتج منبهاً واحداً عند البدء دون تكراره.
- حقول الإضافة الجديدة فارغة دون أعداد أو أوقات أو خيارات مسبقة؛ التاريخ يبدأ بتاريخ اليوم، وتبقى القيم المحفوظة ظاهرة عند تعديل سجل موجود.
- إعداد نغمة المنبه ومراجعة أذونات أندرويد واختبار الرنين، مع اعتماد توقيت غزة `Asia/Gaza`.
- حفظ محلي مشفّر، قفل اختياري بوسيلة قفل الجهاز، نسخ احتياطية مشفّرة بكلمة مرور، وتصدير تقرير CSV.

**كيف تُحسب الجلسات؟** تُخصم الجلسة مرة واحدة من رصيد الطالب عندما تصبح مكتملة ويكون حضوره «حاضر». غياب طالب في جلسة جماعية لا يخصم من رصيده، بينما تُحتسب لزملائه الحاضرين. العدد الأسبوعي هدف في الخطة؛ إنشاء المواعيد يتم من شاشة الجلسات. لا يؤدي تغيير الهدف وحده إلى إنشاء مواعيد تلقائية.

## الحصول على APK من GitHub

1. فكّي ضغط ملف المشروع على الكمبيوتر. ارفعي **الملفات والمجلدات الموجودة داخله** إلى مستودع GitHub جديد، وليس ملف ZIP نفسه.
2. في جذر المستودع يجب أن تظهر `app` و`gradle` و`gradlew` و`settings.gradle` ومجلد `.github`. لا تضعي المشروع داخل مجلد إضافي. ملف تشغيل البناء هو `.github/workflows/build-apk.yml`؛ تأكدي من رفعه حتى لو أخفاه مستكشف الملفات.
3. افتحي تبويب **Actions** ثم **Build APK**. يبدأ البناء بعد رفع الملفات. ويمكن تشغيله من **Run workflow** مع إبقاء خيار `signed_release` غير مفعّل لأول تجربة.
4. بعد ظهور علامة النجاح الخضراء، افتحي التشغيل ومرّري إلى **Artifacts**، ثم نزّلي `ghars-debug-apk`. يجب تسجيل الدخول إلى GitHub لتنزيله.
5. فكّي الضغط عن الملف الذي نزّلته؛ بداخله `app-debug.apk`. انقليه إلى الهاتف وافتحيه، واسمحي بالتثبيت من تطبيق الملفات إذا طلب أندرويد ذلك.

يحتاج **البناء والتنزيل فقط** إلى الإنترنت. استخدام التطبيق نفسه لا يحتاجه. ملف APK الناتج يبقى في Artifacts ثلاثين يوماً وفق إعداد سير العمل، فاحفظي نسخة منه.

نسخة `debug` للتجربة الأولية؛ مفتاحها قد يتغير بين عمليات GitHub، وقد لا يقبل الهاتف تثبيتها كتحديث لنسخة سابقة. **قبل الاستخدام اليومي ببيانات حقيقية، أنشئي نسخة release بمفتاح توقيع دائم** وفق [دليل التوقيع والتحديث](docs/SIGNING.md). نسخة التجربة والنسخة الدائمة لهما هويتان مختلفتان، ويمكن نقل البيانات بينهما بالنسخ الاحتياطي المشفّر. لا تحذفي التطبيق قبل تصدير نسخة قابلة للاستعادة.

إذا استلمتِ ملف APK جاهزاً باسم **غرس · معاينة** مع المشروع، فهو نسخة اختبار مستقلة بمعرّف `ps.ghars.sessions.preview`، ومخزن بياناتها منفصل عن نسختي GitHub. انتقلي منها لاحقاً إلى النسخة الدائمة بتصدير نسخة احتياطية مشفّرة ثم استعادتها في التطبيق الدائم. مفتاح توقيع المعاينة الخاص لا يُضمّن في ملف المشروع.

## أول تشغيل

1. افتحي «الإعدادات»، وامنحي أذونات الإشعارات والمنبهات الدقيقة وعرض المنبه بملء الشاشة بحسب إصدار أندرويد.
2. اختاري نغمة وارْفعي مستوى **صوت المنبه**. استخدمي اختبار المنبه ثم اقفلي الشاشة للتحقق من السلوك على الهاتف نفسه.
3. أضيفي طالباً وخطته، ثم أنشئي جلسة فردية أو اختاري عدة طلاب للجلسة الجماعية. حددي الأيام والتكرار والمدة والتذكير.
4. بعد الجلسة سجلي الحضور والملاحظات لكل طفل واضغطي إنهاء الجلسة.
5. صدّري نسخة احتياطية مشفّرة بانتظام واحفظي كلمة مرورها في مكان آمن منفصل.

### تحديث 1.0.1

يعيد التطبيق جدولة المواعيد المحفوظة لإضافة منبّه البدء تلقائياً، بما فيها الجلسات التي لم يُحدد لها تذكير مسبق. لا يلزم إعادة إنشاء الجلسات. مثال: جلسة الساعة 10:00 وتذكير قبل 30 دقيقة ترن في 09:30 ثم 10:00. إيقاف الرنين الأول لا يلغي منبّه البداية. الإلغاء أو إتمام الجلسة يلغي منبهاتها القادمة.

أعداد الجلسات، وعددها الأسبوعي، والمدة، والوقت، ومدة التذكير وأسابيع التكرار أصبحت فارغة عند الإضافة. اختاري النوع والفترة وأيام التكرار بنفسك. إذا كانت خطة نوع علاج غير مطلوبة، اتركي حقليها معاً فارغين. تفاصيل التحديث والتثبيت في [دليل تحديث 1.0.1](docs/UPDATE-1.0.1.md).

أندرويد لا يستطيع تشغيل منبّه من تطبيق عندما يكون الهاتف مطفأ، أو بعد **فرض إيقاف** التطبيق حتى يُفتح مجدداً. بعض الهواتف تحتاج السماح بالعمل في الخلفية. عند رفض إذن المنبه الدقيق قد يتأخر التنبيه ويُستخدم إشعار بديل؛ تحققي من صفحة الإعدادات. تفاصيل الإعداد والقيود في [دليل المنبّه](docs/ALARMS.md).

## حفظ بيانات الطلاب

لا يحتوي التطبيق على إذن الإنترنت ولا تحليلات استخدام أو خدمات سحابية. تبقى بيانات الطلاب في مساحة التطبيق الخاصة ومشفّرة بمفتاح الجهاز. **حذف التطبيق أو مسح بياناته يحذف السجل المحلي ومفتاحه**؛ النسخة الاحتياطية المصدّرة هي وسيلة الاستعادة والنقل إلى هاتف آخر.

كلمة مرور النسخة الاحتياطية لا تُرسل إلى أي جهة ولا توجد خدمة لاستعادتها. **فقدان كلمة المرور يعني تعذّر فتح النسخة**. الاستعادة تستبدل السجل الحالي كاملاً بعد التأكيد ولا تدمجه؛ صدّري نسخة حديثة قبل الاستعادة. تقارير CSV ملفات نصية غير مشفّرة وقد تحتوي أسماء الطلاب وملاحظاتهم؛ اختاري مكان حفظها بعناية. راجعي [الخصوصية والنسخ الاحتياطي](docs/PRIVACY.md).

## البناء على الكمبيوتر

المشروع يحتوي على Gradle Wrapper حقيقي. المتطلبات: JDK 17 أو 21، وAndroid SDK Platform 35 وBuild Tools 34.0.0، وNode.js 22 لتشغيل اختبارات الحساب والجدولة. يعمل المشروع مع AGP 8.7.3 وGradle 8.9، وهي مجموعة تدعم API 35 وفق [وثائق Android الرسمية](https://developer.android.com/build/releases/agp-8-7-0-release-notes).

افتحي المجلد في Android Studio وثبّتي المنصة المطلوبة. أو أنشئي ملف `local.properties` محلياً يحتوي `sdk.dir` لمسار Android SDK، ثم شغّلي من مجلد المشروع:

```powershell
node --test tests/*.test.js
.\gradlew.bat lintDebug testDebugUnitTest assembleDebug
```

على Linux أو macOS: استخدمي `chmod +x gradlew` ثم `./gradlew` بدلاً من `gradlew.bat`. أول بناء ينزّل أدواته من الإنترنت. ملف APK يوجد في `app/build/outputs/apk/debug/app-debug.apk`.

واجهة التطبيق مكتوبة بـ HTML/CSS/JavaScript داخل WebView محلي؛ التخزين والتشفير والمنبّه والصلاحيات مكتوبة بـ Java ضمن تطبيق Android. معاينة الواجهة في متصفح الكمبيوتر لا توفر منبهات أندرويد أو الحفظ المشفر أو نقل النسخ الاحتياطية، وتُعرّف نفسها كمعاينة.

اختبارات المشروع وخطوات تجربة الهاتف موضّحة في [دليل التحقق](docs/TESTING.md). نجاح بناء APK وحده لا يثبت عمل المنبّه على جميع الشركات المصنّعة؛ يلزم تنفيذ تجربة الهاتف.

## محتويات المشروع

| المسار | وظيفته |
| --- | --- |
| `app/src/main/assets` | الواجهة العربية والشعار وحسابات الجلسات |
| `app/src/main/java/ps/ghars/sessions` | وظائف Android والتخزين والتشفير والمنبه |
| `app/src/test` و`tests` | اختبارات التشفير والحساب والجدولة |
| `.github/workflows/build-apk.yml` | بناء APK وفحوصات GitHub |
| `docs` | إرشادات المنبّه والخصوصية والتوقيع والتحقق |

الشعار من الملف المرفق من صاحب الطلب، للاستخدام باسم المدرسة. لا توجد بيانات أطفال حقيقية أو مفاتيح توقيع خاصة داخل المشروع. لا ترفعي نسخ الطلاب أو تقاريرهم أو مفاتيح التوقيع إلى المستودع.
